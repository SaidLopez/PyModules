# Type-routed module registry; handlers return responses

The previous handler contract had every `Module` re-implement `isinstance` checks twice (once in `can_handle`, once in `handle`) while the host iterated every registered module on every dispatch. The handler signature was `def handle(self, event) -> None` with the response written by mutating `event.output` and the dispatch terminated by setting `event.handled = True`. Both patterns came from NetModules' C# lineage and read awkwardly in Python: nullable `output` fields, a `handled` flag whose only job was to signal "function would have returned a value if it could," and O(N) dispatch on every command.

We adopted a type-routed registry with **method-level handler decoration**: each handler is a method on a `Module` subclass decorated `@handles(CreateUser)` (one method per **Command** class). `ModuleHost` scans the class at registration and builds a `{CommandClass → bound method}` table. Handlers now **return** their response (`@handles(GreetCommand) def greet(self, command: GreetCommand) -> GreetResponse`), which eliminates `Command.response` as a mutable field, eliminates the `handled` flag, and eliminates the dispatch-loop early-break.

The method-level form was chosen over a `commands = [...]` class attribute because every existing **Module** in the codebase handles exactly one **Command** and writes a redundant `isinstance` check at the top of `handle()` — `can_handle` had already proven the type. Method-level decoration deletes that dead branch, gives each handler a precise typed signature (eliminating the framework-level `Any` return), and makes "what does this Module handle" introspectable from one source of truth (no `commands = [...]` list that can disagree with the body).

## Consequences

- The typing is strict end-to-end: `Command` is `Generic[Req, Resp]`, the `@handles(C)` decorator verifies (under mypy) that the decorated method signature is `(self, cmd: C) -> Resp`, and `ModuleHost.dispatch(cmd: Command[Req, Resp]) -> Resp` propagates the response type to the caller. A handler that declares `@handles(CreateUser)` but returns `GreetResponse` fails type-checking at definition time, not at runtime.
- Dispatch is O(1) by command class. `can_handle` is removed entirely. Every existing `can_handle` body in the codebase is either an isinstance check (subsumed by the registry) or a test sentinel — no real predicate routing exists. Users who need conditional routing split into narrower **Command** classes; users who need conditional acceptance branch inside the handler body and raise a domain exception. This deletes the predicate-overlap problem that per-method `when=` predicates would have introduced.
- Duplicate command claims are forbidden at registration time: `host.register(SecondModule())` raises if `SecondModule.commands` overlaps any already-registered module. An `override=True` keyword permits deliberate replacement (e.g., test doubles).
- Every existing handler in user code is rewritten. The mutate-in-place collaboration pattern (module A sets one field, module B sets another) is no longer possible — but that pattern was already unsupported by the single-winning-handler semantics, so this is making explicit what was already true.
- `Command.handled` and `Command.output` cease to exist. `Command` carries `request: Request`, `name: str`, and `meta: dict`.
